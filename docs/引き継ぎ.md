## 作業上の注意（今回つまずいた点）

- リポジトリ直下の `.codex-memory.json` と `AGENTS.md` はユーザー側で作られたもの（Codex 用と思われる）。コミットに含めない

- 本番の施設データを直すときは、必ずその日に書き出し直してから直す（操作者が日々変更している）。直したら変更前後で違反チェックの件数を比べ、変わったマスが意図どおりかを数える
- 違反チェックは月ごとなので、月をまたぐ夜勤→翌月1日の明は「夜勤なしの明」と出る（既知の制約）

- 第三恵光の施設データは、職員名を含むためリポジトリに置いていない。作り直すときは施設の資料（同フォルダの Excel・Word）から組み立て直す。
  手元での生成の試し方: 一時的な vitest ファイル（コミットしない）で JSON を読み、`generate()` を呼ぶ
- 入浴日（火・木・土）の日勤5名はこちらの仮決め。施設に確認が取れたら条件画面で変える

- **本番の users に管理者権限（role: admin）を書き込む操作は、auto mode の分類器が止める。** Firebase コンソールでユーザー本人に入力してもらう
- Firebase コンソールで prod を開くには、prod 権限のある Google アカウント（takuronron@gmail.com、URL の `/u/1/`）に切り替える必要がある。Firebase CLI もこのアカウント
- Chrome 拡張で「書き出す」などのボタンを押すときは、`form_input` や ref クリックでは React に届かないことがある。ページ内 JS で select の値を設定して change を発火し、`button.click()` する
- ダウンロードフォルダのファイルは `file_upload` に直接渡せない。scratchpad にコピーしてから渡す（職員名入りのファイルは使用後に削除）
- 生成中はページが固まるので、Chrome 拡張の JS 実行は45秒でタイムアウトする。生成開始と結果の読み取りは別の呼び出しに分ける
- アイコンを直すときは `scripts/build-icons.mjs` の `ART` を編集して `npm run icons`（手元の Chrome を使う）
- アミティの C1（29・30日）と第二女性棟の Dh/d2 の必須違反2件は、人手の上限による構造的なもので、直す対象ではない
