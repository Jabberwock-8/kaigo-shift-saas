## 作業上の注意（今回つまずいた点）

- **本番の施設データを直すときは、必ずその日に「書き出す」でバックアップを取り、それを直して「読み込む」。** 操作者が日々変更しているため古いファイルは使わない。
  直した前後で、既存の文書が変わっていないか（追加だけか）・違反チェックの件数が同じかを数えてから読み込む
- 施設データの作り直し・変換のスクリプトは職員名を含むためリポジトリに置かず scratchpad に置いた（次のチャットでは消えている前提）。
  手元での生成の試し方: 一時的な vitest ファイル（コミットしない）で JSON を読み、`generate()` を呼ぶ
- Chrome 拡張（Claude in Chrome）の操作
  - ボタン・select は `form_input` や ref クリックでは React に届かないことがある。ページ内 JS でネイティブの value setter を使い input/change を発火して `click()`
  - 「この内容で読み込む」は confirm() が出るので、一時的に `window.confirm = () => true` にしてから押す
  - ダウンロードフォルダのファイルは `file_upload` に直接渡せない。scratchpad にコピーしてから渡す（職員名入りは使用後に削除）
  - 同じサイトからの連続ダウンロードは Chrome が止める。ユーザーが「自動ダウンロードを許可」済み（2026-10-21）
  - 拡張がつながらないときは、ユーザーに Chrome の起動と Claude サイドパネルのログインを頼む
  - 生成中はページが固まり JS 実行が45秒でタイムアウトする。生成開始と結果の読み取りは別の呼び出しに分ける
- シェルで node -e にバッククォート入りの文字列を渡すと bash に展開されて壊れる。長い置換はスクリプトファイルを Write してから実行する
- 本番の users に管理者権限（role: admin）を書き込む操作は auto mode の分類器が止める。Firebase コンソールでユーザー本人に入力してもらう
- Firebase コンソールで prod を開くには takuronron@gmail.com（URL の `/u/1/`）に切り替える。Firebase CLI もこのアカウント
- 月をまたぐ夜勤明け・連続勤務は、前月の勤務表があれば前月末を引き継いで生成・チェックする（2026-10-28。前月の勤務表が無い月は1日の明を「夜勤なし」としない）
- アミティの C1（月末）・第二女性棟の Dh/d2・各施設の月末の夜勤/M3 の必須違反は、人手の上限による構造的なもの
- リポジトリ直下の `.codex-memory.json` と `AGENTS.md` はユーザー側のファイル。コミットに含めない
- アイコンを直すときは `scripts/build-icons.mjs` の `ART` を編集して `npm run icons`
